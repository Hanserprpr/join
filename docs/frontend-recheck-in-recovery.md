# 关闭签到后的过号恢复

场次结束只关闭新签到，已有候选人仍可继续面试。使用 `RECHECK_IN` 过号模式时，
本人处于 `RECHECK_IN_REQUIRED` 的签到记录可以在关闭签到后恢复排队。

使用现有接口和参数：

```http
POST /api/check-ins
Content-Type: application/json

{"departmentId": 12, "sessionId": 30}
```

- `sessionId` 使用该候选人排队状态中的场次 ID，无需从已发布场次列表重新选择。
- 关闭签到后恢复已有过号记录无需二维码令牌，原来要求扫码的场次也适用。
- 有效二维码或已捕获的扫码凭证仍可用于恢复；过期令牌依旧返回原有令牌错误。
- 恢复沿用原签到记录，重新取号并排到队尾，保留过号次数，不重新授予顺延优先资格。
- 没有本场签到记录的用户不能借此新加入；正在面试或已面试的用户不能重复恢复。
- 恢复成功后继续使用原响应结构和队列 SSE；重复恢复返回已有的重复签到错误。
- 场次仍开放签到时，原有扫码要求继续生效。

前端在个人状态为 `RECHECK_IN_REQUIRED` 时展示“重新排队”，不要因场次结束而禁用该按钮。
